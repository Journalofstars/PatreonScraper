# 打包说明

把项目打包成**脱离 Python 也能运行**的独立 exe。

## 一条命令

```bat
build.bat
```

约 45 秒后产物在 `dist\PatreonDownloader\`：

```
dist\PatreonDownloader\
├── PatreonDownloader.exe      ← 双击运行
├── 启动.bat
├── README.md
├── data\                      ← 运行时数据，跟着 exe 走
└── _internal\                 ← Qt / Python 运行时
```

**整个文件夹拷到任意 Windows 机器都能直接跑，不需要装 Python。**

## 参数

| 命令 | 作用 |
| --- | --- |
| `build.bat` | 默认，无控制台窗口 |
| `build.bat --console` | 保留控制台，**首次打包或排查问题时建议用这个** |
| `build.bat --fresh` | 强制重装 PyInstaller |
| `build.bat --keep-build` | 保留中间产物 `build\`，便于看收集了哪些文件 |

手动等价步骤：

```bat
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.venv\Scripts\python.exe tools\build_exe.py
```

## 打包后怎么验证

产物自带自检模式，会检查数据目录、Qt 平台插件、网络库和**内置浏览器**：

```bat
dist\PatreonDownloader\PatreonDownloader.exe --selftest
```

无控制台的版本看不到输出，报告写在 `data\logs\selftest.log`：

```
Patreon 内容下载器 自检（v1.0.0）
冻结打包: True
数据目录: ...\dist\PatreonDownloader
----------------------------------------------------------
[通过] 数据目录可读写 — ...\dist\PatreonDownloader\data
[通过] HTTP 客户端 — requests 2.34.2
[通过] Qt 平台插件 — windows
[通过] 访问 patreon.com — HTTP 200，335203 字节
[通过] 内置浏览器 (QtWebEngine) — QWebEngineView 可加载页面

```

退出码 `0` = 全部通过，非 0 = 有项目失败。源码运行也可以用 `main.py --selftest`。

## 三个必须知道的实现细节

### 1. 数据目录要跟着 exe 走

源码运行时 `data/` 在项目根目录；打包后如果继续用 `Path(__file__).parent`，
会指向 PyInstaller 的**临时解包目录**，导致**每次启动配置和登录凭证全丢**。

[config.py](../patreon_dl/config.py) 的 `_resolve_app_dir()` 会检测 `sys.frozen`：

```python
if getattr(sys, "frozen", False):
    beside = Path(sys.executable).resolve().parent
    if _is_writable(beside):
        return beside
    # 装在 Program Files 之类不可写的位置时退回用户目录
    return Path(os.environ["LOCALAPPDATA"]) / "PatreonDownloader"
```

也可以用环境变量 `PATREON_DL_HOME` 手动指定。

### 2. 无控制台的 exe 里 `sys.stdout` 是 `None`

这是个很隐蔽的坑：**`print()` 对 `None` 是静默跳过的**（CPython 内部
`if (file == Py_None) Py_RETURN_NONE`），所以日志看着正常，但
`sys.stdout.flush()` 会抛 `AttributeError: 'NoneType' object has no attribute 'flush'`，
表现为「自检明明全过，退出码却是 1，还多了个 crash.log」。

所以 [app.py](../patreon_dl/ui/app.py) 里：

- 写 stdout / stderr 前一律判空；
- 没有控制台时，自检结果改用 `QMessageBox` 弹窗展示。

### 3. QtWebEngine 退出时会段错误

自检能跑通，但正常 `return` 会让进程以 `0xC0000005`（访问冲突）结束，
看起来像自检失败。原因是 QtWebEngine 的 profile / page 销毁顺序很脆弱。

处理：

- 自检用与登录窗口相同的**进程级共享 profile**（它活到进程退出）；
- 报告写盘后在 `_run_selftest()` 里直接 `os._exit(0/1)`，让退出码如实反映结果。

## 体积

| 项目 | 大小 |
| --- | --- |
| 总计 | **约 470 MB** |
| `Qt6WebEngineCore.dll` | 194 MB |
| `opengl32sw.dll`（软件 OpenGL 兜底） | 20 MB |
| Qt / Python / 其它 | 剩余 |

`patreon_dl.spec` 里已经剔除了三类用不到的东西，合计省下约 **128 MB**：

| 剔除内容 | 省下 |
| --- | --- |
| `*.debug.pak` / `*.debug.bin`（Chromium 调试用资源） | ~77 MB |
| QtWebEngine 的 53 个语言包，只留 `en-US` 和 `zh-CN` | ~42 MB |
| Qt 自带翻译，只留简体中文（英文内置无需文件） | ~9 MB |

### 不建议做的两件事

- **别去掉 QtWebEngine**：那是 194 MB 的大头，但「内置浏览器登录」正是这个程序的
  核心（`session_id` 是 HttpOnly 的，只能从浏览器 Cookie 存储里拿）。
  去掉的话就只剩手动粘贴 Cookie 了。
- **别对 Qt 的 dll 用 UPX 压缩**：压过之后经常加载失败。

## 为什么用 onedir 而不是 onefile

QtWebEngine 有约 400 MB 运行时，onefile 每次启动都要把它们解压到临时目录：

- 启动要十几秒；
- 更容易被杀软误报；
- 出了问题不好排查缺哪个 dll。

onedir 启动快、结构可见，是这类 Qt 应用的标准选择。

## 备选：Nuitka

Nuitka 会把 Python 编译成 C 再编译成原生二进制，启动更快、更不容易误报，
但构建慢得多，且 `PySide6 + QtWebEngine` 的组合需要额外折腾：

```bat
.venv\Scripts\python.exe -m pip install nuitka
.venv\Scripts\python.exe -m nuitka --standalone --enable-plugin=pyside6 ^
    --include-qt-plugins=webengine,network,svg ^
    --windows-console-mode=disable ^
    --output-dir=dist-nuitka main.py
```

一般用途用 `build.bat`（PyInstaller）就够了；只有在意启动速度或杀软误报时才考虑 Nuitka。
