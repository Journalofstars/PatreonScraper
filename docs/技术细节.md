# 技术细节

README 里放不下的实现细节都在这里。所有结论都是对着 Patreon 线上接口实测出来的。

## API 端点

| 用途 | 请求 |
| --- | --- |
| 创作者信息 | `GET /api/campaigns/{campaign_id}?include=creator,rewards` |
| 作品列表 | `GET /api/posts?filter[campaign_id]=…&sort=-published_at&page[count]=…&page[cursor]=…` |
| 单篇作品 | `GET /api/posts/{post_id}?include=…&fields[post]=…` |
| 单个媒体 | `GET /api/media/{media_id}` |
| 当前用户 | `GET /api/current_user` |

分页游标在 `meta.pagination.cursors.next`，请求时用 `page[cursor]` 回传。

**`fields[post]` 白名单里必须包含 `content_json_string`**，否则服务端不会返回新版正文，
正文里内嵌的媒体就完全看不到（见下文）。

创作者 ID 的解析：主页 HTML 里的 `/api/campaigns/(\d+)` 最稳；
`parse_reference_all()` 会给出多个候选（去掉 `/c/` `/cw/` `/user` 等前缀后的段、
以及原始路径段），逐个尝试，Patreon 换新前缀时不会立刻失效。

## 媒体地址从哪来

**图片**：`media.image_urls` 里按画质取
`original` → `default_large` → `default` → `thumbnail` 逐级回退。

**视频**有三种情况：

1. `media.download_url`，`mimetype` 为 `application/x-mpegURL` 时通常是
   `https://stream.mux.com/<playbackId>/highest.mp4?token=…`，即**完整视频**；
2. `post.attributes.post_file.url` 里的 `.m3u8`（新版格式），带同一个播放 ID，
   可以换成 `highest.mp4`；
3. 其它 `video/mp4` 直链多半是 30 秒预览，由「视频预览片段」开关控制。

**mux 令牌必须验 `aud` 字段**：

| 令牌 | `aud` | 用途 |
| --- | --- | --- |
| 视频 | `v` | 可取 `highest.mp4` / `.m3u8` |
| 封面图 | `t` | `image.mux.com/.../thumbnail.jpg`，拿去请求视频会 **403** |
| 故事板 | `s` | `storyboard.vtt` |

程序解码 JWT 的 payload（只读，不验签名），只接受 `aud` 为 `v` 的令牌，
并跳过 `/text/`、`/storyboard`、`/thumbnail`、`.vtt`、`.json` 这类非视频地址。

## mux 受保护播放（无静态 MP4）

部分视频的令牌里带 `playback_restriction_id`：

```json
{"sub": "Ofqx…", "exp": 1791284400, "aud": "v",
 "playback_restriction_id": "Ir02FmqsqUnMIpEqH89MdlvWa15QwOo6dCnelCtSI9YI"}
```

此时 mux **不提供任何静态 MP4**，请求 `highest.mp4` 会得到
`404 {"error":{"messages":["MP4 does not exist"]}}`；但 `.m3u8` 是 200 可用的
（签名在 URL 里，不是内容加密）。

处理方式：

1. 识别到 `playback_restriction_id` 就跳过静态 MP4，直接用 HLS；
2. `.m3u8` 主播放列表 → 选最高码率 → 顺序下载分片拼接；
3. 这些分片是 **MPEG-TS**（没有 `EXT-X-MAP`），所以拼出来不是合法 MP4，
   再用 **ffmpeg `-c copy`** 无损封装成 MP4；
4. 没有 ffmpeg 时保留 `.ts`，扩展名按实际格式决定。

下载器还支持 `#EXT-X-BYTERANGE` 分片（按 `Range` 头请求）。

## 新版富文本正文（`content_json_string`）

Patreon 有两代编辑器：

- 旧版：正文在 `content` 字段（HTML）；
- 新版：正文在 `content_json_string`，是一个 ProseMirror 文档，
  **媒体以 `media_id` 内嵌在正文里**：

```json
{"type":"video","attrs":{"fallback_strategy":"fallback","media_id":"739888749"}}
```

这类媒体**完全不在** `relationships`（`media` / `images` / `attachments_media`）里，
所以只看关系字段的话，无论从主页列表还是从单篇作品都抓不到——
一篇「索引贴」里 21 个视频只会显示 1 张封面图。

处理方式：

1. `fields[post]` 里带上 `content_json_string`；
2. `parse_rich_content()` 遍历文档，收集所有内嵌 `media_id`；
3. 对每个 ID 调 `GET /api/media/{id}` 取回媒体对象（响应含 `download_url`，
   结构与关系字段里的一致）；
4. `media_resolver` 会先用页面响应里已有的媒体对象，没有再发请求——
   普通作品因此**零额外请求**。

因为要逐个请求，设置里给了开关「正文里内嵌的媒体」，默认开启。

### 按部分分组

正文里每个媒体前面的那段文字就是它的标题，但**不一定是 heading**，也可能是
`blockquote`：

```
[3]  blockquote 'Your Bratty Girlfriend Loves Bond*ge...'   ← 标题
[4]  video       739888749
[16] heading L2  'Bully Series Arcs'                        ← 分类
[19] heading L3  'Part 1 [Handj*b] :'                       ← 标题
[21] video       739906981
```

`parse_rich_content()` 因此按这个规则分组：

- 维护 **heading 层级栈**（遇到更深层 heading 时清掉更深的层）；
- 维护「最近一段非空文字」（heading / blockquote / paragraph 都算）；
- 每个媒体的小标题 = **heading 路径 + 最近的文字**，去掉重复项。

这样上例里两个同名的 "Part 1" 会分别得到
`Bully Series Arcs - Part 1 [Handj*b]` 和 `School Festival Arc - Part 1 [Handj*b]`。

「帖子内含多个部分时，每个部分单独建子目录」打开后，`build_tasks()` 按
`MediaItem.section` 分目录，每个目录内文件从 `01_` 重新编号；
**只有 2 个以上部分的帖子才拆分**，普通帖子不受影响。

## 增量判断：相对路径而非绝对路径

`data/state.json` 里每条记录同时存：

```jsonc
"171238686:m756567987": {
  "rel":  "NSFW VTuber Roleplay Videos\\2026-10-03_标题\\02_封面.png",  // 判断用这个
  "path": "G:/bb\\NSFW VTuber Roleplay Videos\\2026-10-03_标题\\02_封面.png",
  "size": 301618, "kind": "image"
}
```

`MediaItem.key` 是稳定标识（`{post_id}:m{media_id}`，没有 media_id 时用去掉签名
参数的 URL 指纹 `stable_url_key()`），所以多次抓取能对上同一条记录。

`StateStore._candidate_paths()` 只认**当前下载目录内**的位置，按可信度排序：

1. `<当前下载目录>/<rel>`；
2. 记录的绝对路径，**前提是它仍在当前下载目录内**；
3. 用绝对路径的尾部在当前下载目录里逐级找回（老记录 / 已换目录）。
   这属于猜测，**必须大小完全吻合**才认，避免同名文件误判。

命中后就地**自愈**：把 `path` / `rel` 更新成新位置，下次直接命中。
所以把整个下载目录从 `G:/bb` 搬到 `E:/bb` 再改设置，依然算已下载；
而不在当前下载目录里的文件一律不算——这就是「只考虑下载目录中的内容」。

## 几个不直观的坑

| 现象 | 原因 |
| --- | --- |
| 静态 MP4 全部 404 | 受保护播放不给静态 MP4，只能走 HLS（见上） |
| 视频 403 | 误用了封面图令牌（`aud: "t"`），或令牌过期 |
| 下载体积和接口报的 `size_bytes` 不一致 | 接口报的是源片大小，程序下的是 `highest` 清晰度并重新封装。所以这个数字**只用于界面显示**，不参与「已下载」校验，否则每次都会重下 |
| 字幕 / 故事板被当成视频 | 已按 `aud` 和路径特征排除 |
| 创作者页 `/cw/xxx` 解析失败 | 路径前缀表已覆盖 `c` / `cw` / `user` 等 30 多个，并会跟随跳转 |

## 限流与重试

`PatreonClient.request()` 统一处理：

- `429`：读 `Retry-After`，等待后重试（上限 120 秒）；
- `5xx` / 网络错误：指数退避重试，次数由设置里的「失败重试次数」决定；
- `401 / 403`：抛 `AuthError`，界面提示重新登录；
- `404`：抛 `NotFoundError`；
- 返回 HTML 而不是 JSON：提示登录失效或触发了人机验证。

请求间隔由设置里的「请求间隔」控制，默认 0.35 秒。
